The Challenge

Scope

What we were designing

The core building blocks are objects: reusable risk detection components that policies draw on to evaluate content, covering areas like lexicon usage and preapproved content.

The tasks compliance administrators perform follow a consistent pattern. Two primary tasks and a set of secondary tasks recur across every object type.

Objects → policies: how risk detection components relate to compliance workflows

Reframing the Brief

From visual refresh to defined user need

The initial framing was a simple visual refresh. I shifted the conversation toward a defined user need: reduce the mental friction compliance administrators experience when navigating between topics, and give them a consistent, predictable experience that doesn't require relearning the product each time.

"Calling it a visual refresh kept the discussion at the surface level. By defining the underlying user need, I turned it into a problem stakeholders could understand, prioritize, and invest in."

Final Brief

What we aligned on

The goal was to establish a coherent, system-level approach to build the infrastructure that would let the product improve holistically over time.

The expected outcomes were a reusable template addressing common object tasks, development-ready designs for creating and modifying Keyword Lists, and full workflows adoptable by both designers and engineers.

Stage 01 — Abstraction

Finding the structure beneath the surface

A content audit resulted in a clear content structure that could serve as a shared reference. This was validated with UX designers working on overlapping initiatives.

Content audit — identifying patterns and focus

From this foundation, two shared patterns emerged that would carry across every object type: the Header and Details & Metadata. These became the basis for a reusable template — a common starting point regardless of which compliance topic a designer or engineer was working in.

Stage 02 — Application

Testing the system with Keyword Lists

To move on from abstraction and design real-world applications, we started with Keyword Lists. This gave us specific content and user journeys to start applying to the structure we defined earlier.

Reflection

What I'd do differently

Setting expectations early was one of the most important things we did — and it still wasn't early enough. A clearer project brief from the start would have saved time when timelines and priorities needed renegotiating. I now treat the brief as a living document and revisit it with stakeholders at the beginning of each stage, not just at kickoff.

The content design phase was also underestimated. The content audit turned out to be foundational to everything that followed — but it wasn't scoped that way initially. In future projects I'd treat content structure as a first-class deliverable, not a prerequisite to the "real" design work.
